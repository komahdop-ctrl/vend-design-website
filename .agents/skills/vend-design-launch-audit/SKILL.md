# VEND DESIGN: проверка перед публикацией

Рабочий проект: `komahdop-ctrl/vend-design-website`, статический HTML/CSS/JS и WebP в `assets/`. Главная ветка `main`, автоматическая публикация GitHub Pages при push. Основной заявленный домен — `vend-design.ru`; доменные настройки документированы в `DEPLOYMENT.md`.

## 1. Подтверди фактическое состояние
- Прочти актуальные `README.md`, `DEPLOYMENT.md`, `.github/workflows/deploy-pages.yml`, `CNAME`, `index.html`.
- Разделяй: что прямо видно в исходниках; что прошло в CI; что подтверждено HTTP/DNS в реальном времени; что не удалось проверить.
- Успех CI ≠ проверенная доступность основного домена, исправность HTTPS и работоспособность каждого сценария.
- Не меняй DNS, ветку `main`, настройки публикации и реальных получателей заявок без отдельного явного разрешения.

## 2. Статический аудит
- Сверь все `src` и `href` с реально существующими локальными файлами.
- Проверь корректность заголовков, alt, labels, фокуса, контраста, порядок табуляции, мобильное меню и видимость элементов на ширинах 320, 375, 768 и 1440 px.
- Отдельно проверь фильтр галереи, полноэкранный просмотр, закрытие Escape/по крестику, ползунок до/после, возврат фокуса.
- В форме проверь обязательность модели, выбранные значения, кодирование кириллицы в `wa.me`, запасной почтовый контакт. Никогда не отправляй тестовые заявки реальному получателю.
- Не называй визуализации сделанными заказами или реальными монтажами. Проверяй соответствие цены, комплектации и оговорок бизнес-условиям; не придумывай скидки или сроки.

## 3. Браузерная проверка
- Для локального статического сайта можно запустить `python -m http.server 8000` из корня и Playwright-тесты без внешних аккаунтов.
- Проверяй консоль браузера и сетевые запросы; записывай шаги, ожидаемое и фактическое поведение.
- Не объявляй тесты прошедшими, если браузер/домен недоступен. Зафиксируй ограничения.

## 4. Публикация и проверка домена
- Сначала проверь актуальную документацию GitHub Pages и записи DNS у фактического DNS-провайдера: A/AAAA для корня, CNAME для www, CNAME в репозитории, сертификат HTTPS и редирект.
- Не затрагивай MX/TXT/NS записи и остальные домены. Не повторяй старые инструкции без проверки.
- После разрешённой публикации сделай GET/HEAD для корня, www, CSS/JS/изображений, robots.txt и sitemap.xml; проверь мобильный и десктопный сценарии.
- Не выдавай отсутствие ответа из ограниченной тестовой среды за доказательство сбоя сайта для всех посетителей.

## 5. Конфиденциальность и выпуск
- Проверь данные, которые вводит пользователь, переход во внешние сервисы, обработку заявок и описание политики конфиденциальности на фактическую модель обработки.
- Учти сторонние запросы Google Fonts и возможную недоступность WhatsApp; по необходимости предложи локальные шрифты/альтернативный канал.
- Выпускать только после подтверждения всех критических пунктов. Для каждого пункта дай статус: проверено / не проверено / блокирует релиз.

Краткий verdict: `GO` / `NO-GO` / `НЕ УСТАНОВЛЕНО`. Таблица доказательств, 2–5 приоритетных проблем, точные действия и команды для перепроверки.
